# P1-E｜双方真实手部握持与第一人称玩家模型完善

> **待 Codex 执行。** 本轮以 P1-D `a6268b9`（[PR #5](https://github.com/Ihtbfas/armwrestling-vr/pull/5)）为基线。优先处理**玩家与对手两只真实手的握持关系**，其次修复本地玩家裁切手臂的可见边缘。无需等待实物几何数据，不新增复杂动画/物理框架。

## 现状与要解决的问题

- P1-D 已有玩家第一人称 Ch03 局部蒙皮手臂、对手 Ch03、共享单自由度 grip、双手指骨、较稳定的对手肘部和两个真实 Humanoid AnimationClip（`SeatedPrepare` / `SeatedContest`）+ 1D Blend Tree + Animator IK。
- 现有两手的掌心代理点相距约 **30 mm**，但这只是两个代理点之间的距离，不能证明掌面对向、拇指搭扣、指腹接触或网格未穿模。当前仍有局部手指重叠。
- `PlayerArmVisual.cs` 利用本机 Ch03 裁切网格；第三方模型许可未确认，裁切结果及 `.meta` 只留本机。外部相机能看到上臂截断边缘；公开仓库仍需保留胶囊回退。
- P1-D 同输入 ±30°：对手肘骨水平移动范围 48.6 mm（P1-C 为 267.8 mm）、掌心代理到 grip 最大误差约 3.31 mm、最大腕折角约 4.6°；±42° 负端肘部蒙皮代理采样穿入约 2.8 mm。本轮不以极端角 0 穿入为目标，不再重新求解整套肘垫。
- 既有正式 VR 的 PC UDP/STM32/PICO 联调仍独立；本轮纯 Unity Editor 动画与显示，不改变协议或物理装置。

## 本轮优先目标

### A. 两只真实手真正形成合理的扳手腕握姿（最重要）

1. **先看清现状。** 在同一 P1-D Demo 中，通过手部近景 + 第一人称 + 正侧视，观察零位、双方占优与连续往返。检查两只右手的掌心朝向、腕部旋转、拇指搭扣和四指位置。不要一上来只增加手指屈曲角。
2. **明确共享 grip 与两手掌面目标的关系。** 推荐用简单、可调整的手掌参考坐标/锚点（位置 + 朝向，必要时局部偏置），分别驱动玩家与对手的手；共享 grip 仍由现有单自由度角度决定。不同人的手掌不应强迫占据同一点。可直接在现有 `PlayerArmVisual`、`OpponentAvatar` 和相关配置中实现，不要求创建大型手部接触框架。
3. **优先修整体的手掌方向和腕部姿态**，再小幅调整拇指/指节弯曲，让双手看起来互相抓握且保持自然关节范围。保留手与 grip 的相对位置，不以大幅分离两手来掩盖穿模。
4. 在可行的前提下用当前 SkinnedMesh / `BakeMesh` 做简洁的掌面、手指局部采样和前后对照；若能使用双手网格的局部近似碰撞/距离采样可尝试，但**不要把单个掌心代理误差、稀疏采样或碰撞体代理误称为完整网格无互穿**。主目标是有说服力的连续实际画面。

### B. 改善第一人称玩家手臂显示（次要）

1. 在保留当前玩家 Ch03 本机原型的基础上，减少外部视角明显的上臂裁切边缘（如合理隐藏的边界、衣袖/护腕或重新确定裁切区域）。**不要通过移动相机假装解决，也不要破坏第一人称视角**。
2. 尽量让角色/玩家模型的材质和比例协调。没有必要重做整个角色或重建场景；正常 Editor Play 和胶囊回退必须仍能运行。
3. **授权限制：** 原 Ch03 / 衍生裁切网格、第三方模型、贴图、视频不得在许可未确认前上传 Public GitHub。可以快速调查现有素材许可或替换候选；若缺少确认或合适资源，保留本机演示并记录取得明确授权/替换资源的后续事项，不必无限搜索。

### C. 继续复用而不是重做动画

- 保留 P1-D 的两段 Humanoid 动画、Effort Blend Tree、近固定肘部、Animator IK 和统一 grip 运动；只修改与双手接触、玩家模型显示直接有关的内容。
- 对手肘部在垫内适度滑移是合理的，不要为了在极限角追求零毫米而再次重配演示肘垫。
- 不要趁机扩充面部、复杂肌肉、真实物理碰撞、全身 ragdoll、XR SDK 或 PC UDP。
- 代码优先简单、可读、可维护。允许 Codex 自主试验、调整和回退；实验失败时保留 P1-D 稳定模式并如实说明。

## 验证方式与交付

沿用 **Unity 中国版 `2022.3.62f3c1`** 和原 `ArmWrestlingMain`，尽量复用 P1-D 的 `AnimationComparison` 与 P0 流程回归工具。

- 同一画面、同一模型、同一握点输入：至少 `−30°/0°/+30°` 三姿态及一次 181 帧左右的连续往返；有余力再验证 ±42° 边界。
- **重点输出**：第一人称两只手的握持近景、正面/侧面及连续动作。用相同角度和镜头与 P1-D 做前后对照，记录掌面/指部重叠是否明显改善、手掌目标是否漂移、腕部和肘部是否出现倒退；不用死盯某个未经验证的毫米阈值。
- 除数值代理，必要时保存拇指、食指、掌心的接触区域局部截图。区分“目视上改善”“代理采样改善”与“已证实网格无穿模”，不要混写。
- P0 胶囊模式、P1-C 本地 Ch03 原模式、P1-D 动画模式尽可能都通过离线比赛：选角、准备、倒计时、暂停/继续、结算。未经实测不得写通过。不得修改 PC/STM32 仓库或协议。
- 更新少量文档，例如 `docs/P1E-hand-contact-result.md`、README、TASKS；保留本地不公开素材及截图视频在 `.p0-local/`，公开的测试文档只含允许发布的代码和指标。
- 提交并推送 **`feat/p1e-hand-contact`**，可创建 **base=`feat/p1d-character-motion`** 的 PR，**不要自行合并**。最终反馈提交 SHA、运行环境与真实证据路径、关键前后变化和剩余问题。

## 阶段完成判据与自主空间

若能在实际 Editor Play 中看到**明显比 P1-D 更合理的双方握姿**，且实时握点跟随、肘部与比赛流程无回退，即可结束；不要求每指逐毫米无穿模。若手部网格或资源权利成为客观瓶颈，交付最好的可运行原型 + 清楚的阻断说明即可。**先完成再完善，避免为微小误差而不断重建框架。**
