# P1-D｜玩家真实手臂、对手肘部稳定与分层动画原型

> **状态：已完成 Editor 原型。** 基于 P1-C 提交 `63b54b2`。运行、对照指标和本机证据见 [P1-D 结果](../P1D-character-motion-result.md)。

## 现有基础与判断

- 工程：Unity 中国版 **2022.3.62f3c1**；主场景 `Assets/Scenes/ArmWrestlingMain.unity`；原来的程序化搭建入口是 `ArenaFactory` / `RuntimeBootstrap`。
- 当前玩家使用 `VirtualArmRig.cs` 中的胶囊上臂/前臂 + 球体手；对手 Ch03 为本地 Humanoid，使用 `OpponentAvatar.cs` 的 **三档身体平移/旋转插值 + Animator 手脚 IK**。
- 当前 `IdlePose.anim` 无实际动作曲线，三档“姿态”也不是制作好的骨骼 AnimationClip / Blend Tree；因此不要把它宣称为已有完整预制动画。
- P1-B 通过扩大和抬高 **演示** 对手肘垫，把肘部蒙皮代理点下缘平均间隙降至约 2.4 mm，但右肘仍随 grip 的横向位置较明显地移动：`OpponentAvatar` 的 `aim.x` 依赖 `gripX`，IK hint 不能等同刚性肘部约束。
- P1-C 的可选 Ch03 手指握姿降低了指部轻微穿模，**玩家球形手与对手掌面约 13 mm 采样重叠没有改善**；不能再围绕球体无限调整对手手指。
- P1-C 已提供 [实物测量指南](../calibration/physical-measurement-guide.md)，但目前没有装配实测数据。VR 视觉工作先沿用标明为 Demo 的位置关系，未来再做设备/VR 空间对齐。

## 本轮目标（按优先顺序推进，允许自主调整实现）

### A. 为第一人称玩家制作正常的人体手臂显示

1. 优先让玩家侧具有**真正的人体手掌、手指和前臂**，视角需要时再有上臂；不要求完整玩家全身模型。默认桌面离线模拟也应能观察到。
2. 先检查本机已有合法资源（包含本地恢复的 Ch03、原压缩包内资源、可复用的 Humanoid/骨骼），或者使用授权明确的可获取手臂/手模型。允许使用 Blender/Unity 等常规工具自制简单但可辨认的人体网格和骨骼，或沿用/裁切已有可用角色，不要求复杂写实建模。
3. **公开仓库资产许可约束：** 无法确认公开再分发许可的 FBX、贴图、商店模型与第三方动画继续只保留本机。不能因为仓库 MIT 就上传这些资源。若只能在本地运行有模型的效果，要同时保留可公开且可运行的降级展示及准确恢复说明。
4. 玩家手臂的**主握持位置**仍由现有单自由度 `Grip Anchor` 决定；与对手共用同一握持参考，允许必要的左右手掌空间偏置、旋转与手指姿态。不能让模型因贴合画面而脱离角度数据源。
5. 优先使用简单的 SkinnedMesh / Humanoid / Transform + 骨骼约束实现；若现有玩家胶囊 IK 有价值，应保留运动学参考或可切换回退。必要时建立一个清晰的玩家视觉组件，但不要为了“架构完整”大改全部场景代码。

### B. 让虚拟对手的肘部更像真实扳手腕时的支撑点

1. 分开**肘垫接触**与**肘部移动范围**两个问题。现阶段不需要把肘刚性锁死，但希望肘部大体停留在一个小的接触区域，运动中只有合理滑移。
2. 先量化 P1-C 现状中肘关节/蒙皮接触代理的水平移动范围，分析 `aim.x` 跟随 grip 的原因；测试“近固定肘接触目标 + 允许肩/躯干补偿 + 手腕跟随共同 grip”的简洁方案，或根据实际骨骼约束选择更好的办法。
3. **运动学可达性优先**：肩、肘、腕和手的骨长不能任意拉伸；若原演示握点圆弧与近固定肘互相冲突，应清楚写出可达角度/折中方案。可以仅在可行区间内限制肘部滑动，不得因强行压住肘部而使手掌脱离握点、肩膀严重扭曲或模型穿桌。
4. 使用 P1-B 的蒙皮采样思路复核肘垫位置和手掌代理误差；**不要把肘骨原点到垫面 0 mm 当作接触成功标准**。本阶段仍是视觉 Demo，不是实物标定或接触力学仿真。

### C. 开始尝试“真正的预制骨骼动画 + 实时 IK”分层

1. 目前的 `IdlePose.anim` 没有动作曲线。**在保留现有三档身体姿态基线的前提下**，尝试一个最小但真实、可回放的骨骼动画原型，例如坐姿呼吸、轻微肩/脊柱动作、准备或对抗时的躯干变化。能做时提供 1～2 个实际非空 AnimationClip（或源自合法动画资产的可编辑片段）。
2. 让动画由比赛阶段或实时角度控制，再由 IK/接触约束在最后修正手与 grip、肘与垫的关系。可选择 `Animator` 层/Avatar Mask、1D Blend Tree、Animation Rigging 等**现有版本兼容**的做法；若简单骨骼片段 + 现有 IK 已足够，就不要为了概念完整引入复杂新框架。
3. 重点解决“躯干只是整体倾斜”的僵硬观感。身体肩、脊柱或头部能自然参与即可，不需要面部捕捉、全身动态布娃娃、物理驱动、十几个动作片段或者三套角色。
4. 预制动画不得与 IK 同时争抢主握持目标、破坏机械输入或产生明显跳帧。实际工程难以可靠制作非空 Clip 时，可先交付能复现的可替代原型和明确阻断，**不要假装已经做了正式 AnimationClip**。

## 验证建议

优先复用 P1-A/B/C 的 Unity Editor 采集工具，减少重复造工具。

- 同一人物和几何，在 `-30° / 0° / +30°`（可加 `±42°`）以及连续往返中，记录玩家手、对手手、共同 grip 的相对位置；给出正面/侧面和**玩家第一人称视角**的图像或短视频。
- 在相同输入下比较对手肘部的**水平移动范围**、肘部代理与垫面接触、腕折角、掌心代理/实际可见掌面的明显穿插；明确改进与仍未解决之处。不要因只测一个代理点就宣称两只真实手完全无穿模。
- 至少验证玩家不再只能看到球形手（除明确回退模式）、双方运动连续、主握持目标一致、人物正常坐姿、关键比赛状态可见。
- 回归 `ArmWrestlingMain`：默认胶囊基线和可用人物模式的角色选择、倒计时、暂停/继续、结算；必要的 Editor 编译与静态检查。PC UDP、STM32、PICO/PCVR 运行不是本轮必做；未实测的明确标注。
- 原始 Ch03 或其他来源不明的模型截图/录屏留在 Git 忽略目录 `.p0-local/`；公开只上传有权发布的代码、指标和描述。

## 自主权与完成界限

这是一次**有优先级的综合改进任务**，不是要求在一轮中完美完成所有动画：

1. 优先拿到**正常玩家手臂/手掌可见**、**对手肘部运动幅度更合理**这两个实质结果；对于真实骨骼 Clip 至少完成最小可用尝试，并交代可行性。
2. Codex 可以自主选择合法模型/资源、Inspector 参数、简单骨骼约束、动画工具，也可以根据真实观察调整先后顺序，自行解决合理范围内的运行问题，不必逐项请示。
3. 不为构建“理想架构”重写 P0～P1-C，不要盲目升级 Unity/XR 包，不修改 PC 仓库、既有 UDP 字段、STM32，也不要声称已有真实机械/头显空间对齐。
4. 若可用模型资源受授权限制或固定肘运动在当前几何下不可达，保留可运行的最佳阶段结果，说明事实和后续最低成本路径，不要陷入无止境的模型搜索或调参。

交付：尽量完成实际 Editor Play；更新 `docs/P1D-character-motion-result.md`、少量 README/TASKS；明确资源路径和公开限制，提供截图/视频本地位置、可复现操作、前后定量或可观察差异。提交并推送 **`feat/p1d-character-motion`**，可创建以 **`feat/p1c-geometry-handoff` 为 base** 的 PR，**不要自行合并**。

**原则：优先可观察的动画改善；允许合理试错；留住现有成果，后续根据实物数据再做正式空间标定。**
