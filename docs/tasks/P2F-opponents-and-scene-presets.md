# P2-F｜离线扩展真实对手人物和可选场景

> **待 Codex 执行**：PICO 头显在其他同学手边，先完成不依赖设备的**可选人物外观 + 环境场景**。本分支 `feat/p2f-opponents-and-scenes` 从 P2 已收口的 `main` `3f30bdb` 建立；将来 PR base=`main`，不自行合并。已有 `feat/p3-pico-offline-first-test` 是另一条从旧 main 建立的独立 PICO 准备分支，**不要在本分支强推/覆盖它**；后续真机任务应在本分支合并后安全同步 P2-F 的内容。

## 目标与优先级

用户希望增加**正常成年女性、运动风格人物、老年人等对手**，同时改善并增加**场景选择**。重点做能由用户在 Unity 比赛界面里亲自选择的视觉功能，不是继续调 P2-E 手指几毫米的接触指标。已有男角色为微软 Rocketbox `Male_Adult_01`；当前 UI 三种“均衡型/防守型/节奏型”是策略，**不是换模型**。

### 1. 增加几名真正不同的人物（主线）

1. 先读 [模型来源和可用性研究](../research/P2F-character-scene-options.md)、`docs/P2-closeout.md`、`docs/P2A-avatar-and-paired-grip-result.md`、`AGENTS.md`、`Assets/ArmWrestling/Editor/RocketboxAssets.cs`、`GripAvatarProfile`、`RuntimeBootstrap` 和原 Lobby/Hud 代码。
2. **优先导入两位微软 MIT 真实女性**：`Female_Adult_01`（粉色衬衫、牛仔裤）与 `Sports_Female_02`（灰色上衣、运动裤）。只选择实际要用的 FBX/色图/透明图，按路径映射材质，合理降低 2048/4K 原图尺寸，保留许可与源 commit。优先抽取共用 Humanoid 导入工具而不是复制整个 `RocketboxAssets.cs` 或使用全局 Generic importer。验收脸、皮肤、手、衣物非粉白、骨架有效、右手 15/15 指骨有蒙皮权重。
3. **另争取一位明确年长外观的真人角色**：优先调查 MakeHuman / MPFB 的老年预设 + 年龄 slider、兼容 Unity 的 Humanoid 骨骼和每个实际素材许可。目标为自然老年外貌 + 正常服装 + 双手可动。若这项有真实骨骼/材质/许可阻断，请如实留下试验与原因，不要用把年轻人头发染白就虚报已做老人，也不要为了追求老年人物无限阻碍另外两名真实女性与场景。
4. 当前男对手、公开胶囊与本机旧 Ch03 都保留。让新人物通过**已有 Profile** 使用相同 Grip Anchor、Animator/IK、`LegacyHumanoidGrip` 默认和可选 `ImagePairedGrip`；对不同臂长和手型做必要的少量人物专属校准，不重新编写一套 Female/Old 控制器。任何人物因指骨/材质不符合要求，应尽快换样本并记清原因。
5. 新人物及其少量必要资产可在 MIT/CC0 与具体第三方素材许可明确时提交 Public GitHub。不要把原 Ch03/HDRI/私有纹理或全部 Rocketbox 库上传。真实画面比较包括角色正面/侧面、坐姿、近景双手和 Ready/Contest。

### 2. 增加场景主题并做实际可选（同时实施）

- 维持现有默认的暗色霓虹竞技场，**至少再新增一套明显不同的亮色训练馆**；条件允许完成第三套**正式比赛场馆**（赛事标识/聚光灯/比赛氛围），优先在原 `ArenaFactory` 参数化主题和简单场景物体层实现，而不是把场景生成函数复制三份。保留原始桌面、双人坐姿、肘垫、机械握点和比赛角度语义；不同主题**不能改变**这些对战几何和碰撞。
- 真实训练馆有地板/墙面/照明或器材轮廓，正式场馆有比分牌/旗帜/舞台等明显差异；不要只是修改一个颜色。材质/环境可参考 Poly Haven CC0 `Gym 01` 的低分辨率资源，核对许可和文件大小。以 PICO 未来性能为约束，避免大 HDRI 和过多实时光影。
- 角色/场景只加载所选的一份，确保场景切换回当前默认时视觉与 Editor 回归没有退步。

### 3. 真正的游戏内人物与场景选择

- 在 Lobby 增加直观的“**对手人物**”与“**对战场景**”选项，可用简单名称/缩略图。玩家能够使用鼠标点击切换并看到**实际所选人物和环境**，而不只是 Inspector 枚举。
- 原“均衡型/防守型/节奏型”保持为独立的**对抗策略**，其 `OpponentRole` 数值、`SessionEventCode`、PC `character_id` 和 UDP 语义均保持原样，不因男女/年龄偷偷改变力矩或难度。三类选择可任意组合；外观与策略相互解耦。
- 如果人物 Prefab 必须重新实例化，安全地只在准备/下一局之前切换、清理旧 Avatar/IK/Collider/资源引用；不要在 Fight 中热换导致崩溃。历史默认不变，缺模型时给明确提示并回退当前男角色，不要空白人物。

### 4. 同轮测试与交付

- **必须实际用 Windows Unity 2022.3.62f3c1 进入 Play**，用真实鼠标 UI 选择原男/女性/运动风格人物/如可用的老年人，与至少科技竞技场+训练馆，完成角色选择、准备、倒计时、对抗、暂停继续、结算。至少对每个可选 Avatar 跑 0/±30° 和一个短连续角度往返；验证有效 Avatar、15 指骨、手部握持、肩肘、坐姿/肘垫，无新编译或运行错误。
- 公开可查看的 PNG：人物选择页、每种新增真人角色正侧面和手部近景、两/三种场景的相同第一人称视角、至少一个新人物 6 秒连续 GIF。尽量少量图、不掩盖穿模，按 `AGENTS.md` 上传 `docs/validation/p2f-visual/`，注明哪些确实 Editor 实测。Ch03 和未授权第三方素材画面继续只留本机。
- 更新 `README.md`、`TASKS.md` 和 `docs/P2F-opponent-scenes-result.md`：实际完成的模型编号及链接、许可证、Humanoid 指骨与皮肤导入、性能/贴图规模、场景如何选择、哪些人物遇到兼容阻碍、如何回退。支持公开 clone 从零导入后的必要重现检查；**不得把 Android build / PICO 真机未测说成已通过**。
- 允许 Codex 自主调研、选择少量替代资源、实现、测试和修复，**有效方案本轮直接集成到 ArmWrestlingMain**，不要只停在角色下载或静态预览。代码清晰、少扩展、先完成再完善。
- 推送 `feat/p2f-opponents-and-scenes`，创建以 `main` 为 base 的 PR，不自行合并；勿碰 P3 PICO 工作分支、PC/STM32/UDP/实物。若无法完成人物老年版，诚实记录并至少交付可选择的成人女性与新场景。

**完成定义**：用户能在正常离线比赛 UI 中看到多位外观明显不同的真实人物及至少一个新环境，旧男角色、原竞技场和完整比赛没有退步；不以“仓库中多了几个 FBX”当作成功。
