## 核心目标

当前 Rocketbox 外观更真实，但握姿仍似钩爪、手—手与上臂—胸部仍明显穿模。P2-B 已配置 44 个代理并可诊断，却只有有限的事后关节纠偏，且让肘活动和单帧跳动增加。

**本阶段目标是让物理接触真正影响动作，而不是只计算碰撞数量**。同时保留 Unity 优势：动画与成对握姿决定人物想做的动作，局部物理/接触约束负责可行性；机械角度始终是 Grip Anchor 的输入，不追求一个重型全身动力学求解器。

## 可选参考路线（实现方式由 Codex 决定）

**A. 成对预制握姿 + 接触感知逐指闭合（优先研究）**  
中立时有自然的掌面、虎口、拇指与四指初态；运行时在关节合理范围内逐渐闭合，使用指尖/指腹或各骨段近似 Collider、Sphere/Capsule cast 或接触距离检测**停止继续向对方手部穿入**。接触时保留包握效果，避免悬空指尖或突然伸直。应基于最终姿态做约束，不是 P2-B 那种把一组已经相交的手指再随意旋转 14°。持续抓握只需稳定的最终姿态，不必循环张合。

**B. 受物理约束的手/局部肢体跟随（小型可行性比较）**  
在隔离小场景或已有场景中试 Rigidbody + Joint/Velocity Tracking 类方案：动态物理代理追随由 Grip Anchor 决定的目标，被挡住时发生**真实物理响应**。证明可以受阻、恢复且动作稳定；检查相对机械目标的位置误差、延迟、关节抖动。**不要因为“更物理”就允许显示手远离真实握把或大幅震荡**。如果不合适，明确排除，不强迫引入主场景。

**上臂—躯干处理**  
应在可实施方案中一并处理最显眼的上臂—胸部交叠：优先人体姿态协调（肩/躯干/肘点/合理坐姿），必要时用碰撞约束限制局部动作；避免把胸部穿模交换成更严重的肘垫穿入和肘滑移。不要引入全身动态 ragdoll。

## 最小实施路径：从验证直接做到交付

1. **确认现状**：先在 `Use Paired Grip` 的原主场景用 0°、±30°、一趟连续运动记录原始第一人称双手和侧面上臂问题。留当前模式 Off/Diagnose/Correct 作为可比较基线。
2. **可行性试验**：快速验证最有希望的方法（可以 A 为主，并只小试 B）；要看到“接触确实限制继续穿入/物理实体确实受阻”，而非只让 CSV 数值下降。按需选 1～3 个成熟参考，避免无终点查资料。
3. **确认有效立即接入主场景**：新实现由可读的组件与简单 Inspector 开关启用，正常比赛全流程能使用；原 P2-A 与 P2-B Diagnose 作为回退/调试，不能只留下一个单独技术演示场景。处理 Animator / OnAnimatorIK / LateUpdate / FixedUpdate 时序，避免修正被覆盖。
4. **针对性修正**：先让正常视觉零位双手扣握，再确保 −30°、+30° 和往返不严重穿模；同时协调上臂—胸部不再明显相交。保留现有正确骨长与人物正常外观，不为了数字破坏握姿。
5. **实测并交付**：使用 Unity 中国版 `2022.3.62f3c1` 的真实 Editor Play，在同一姿态/相机/机械角输入下比较原 P2-A/P2-B 与最终结果。保存第一人称近景、对手正侧面和连续视频；记录腕到握点、手—手穿入代理/可见蒙皮、手指动作连续性、肘滑移、肘垫接触、上臂—胸部穿入。优先画面真实有效，量化指标辅助判断。

## 必须守住的边界

- **Grip Anchor 的单自由度角度和轨迹不变**；玩家与对手双手正常握持，不允许通过拉开双掌来伪装无碰撞。控制侧机械角与物理刚体视觉偏差要如实记录。

- 本轮只做 Unity/VR 人物和动画；无实际 PICO、STM32、UDP、真实机械测量，不宣称已通过。
