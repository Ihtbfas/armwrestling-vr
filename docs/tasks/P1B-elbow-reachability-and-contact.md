# P1-B｜Ch03 肘垫可达性与握持接触优化

> **状态：桌面 Editor Play 已完成。** 见 [P1-B 实测结果](../P1B-elbow-contact-result.md)。 在 P1-A 完成的 `feat/p1-animation-spike`（提交 `b7bc9d6`）之上继续。P0 PR #1、P1-A PR #2 均暂未合并。**本阶段优先解决现有动画的几何接触问题，不增加新动画框架。**

## 已有事实与本轮目标

P1-A 已在 Unity 中国版 **2022.3.62f3c1** 的正式 Editor Play 中完成对照，推荐 **B：三档身体姿态插值 + A 的手脚 IK**，同一 grip、同一 Ch03、同一 −30°→+30°→−30° 视觉角输入。手掌代理点到 grip 最大约 **3.31 mm**；B 在 +30° 的腕折角约 **4.1°**、右肘骨原点到肘垫平面约 **82 mm**，仍不能认为肘部落垫；肘部投影落在垫内 **98/181 帧**。对照结果见 [P1-A 报告](../P1-animation-ab-result.md)。

本阶段希望在**保留 B 的实时握持跟随能力**前提下，让 Ch03 的坐姿、右肘与肘垫、手腕及手部关系在连续对抗角度中合理，形成可复用的几何标定基线。

**请先判断约束是否几何上同时可行，再调 IK。** 这不是只把 IK hint 挪到垫上就完成的任务。

## 关键事实与注意事项

- Unity 当前 `ArenaFactory` 的 `SwingLength=0.30f`、模型位置/缩放、座椅与肘垫尺寸属于演示几何，尚未完成真实机械空间标定。
- 当前右手 IK 使用 grip 回退约 45 mm 的腕部目标；右肘 hint 在 `OpponentAvatar` 中会根据 grip 的 x 位置移动，不代表真实肘部固定接触。
- 报告估计 **Ch03 前臂约 242 mm**。请以 Unity **当前 FBX / 骨骼真实运行长度与缩放**复核（包括手腕、手掌握持偏置），不要把 242 mm 当成已确定的人体标定值，也不要直接更改骨长以迎合位置。
- 当前 P1-A 的“肘部高度”是 **肘骨原点到肘垫平面的距离**。真实承压的是肘部皮肤/软组织；骨骼原点不是接触点，**不要追求肘骨原点到平面等于零**。同理“掌心代理点到 grip 3.31 mm”不是手指闭合或网格无互穿证明。
- 原 PC 项目曾对单轴圆弧与固定肘部可达性进行建模，文档：`Ihtbfas/armwrestling/docs/trajectory-fit.md`。结论是主轴位置和肘部/手腕偏置会决定可达性，**不是换个 IK 一定能修好**。PC 中的候选几何也不是已确定的实物尺寸；不要改 PC 仓库或直接照搬坐标。
- 公开 GitHub 尚不包含授权未明确的 Ch03 FBX/HDRI/字体；本地可按 `docs/third-party-assets.md` 恢复。继续遵守资源授权和 Git 忽略规则。

## 工作内容（允许自主选择实现）

### A. 快速诊断：可达范围与接触定义

1. 保留当前可运行 P1-A，读取 `OpponentAvatar.cs`、`ArenaFactory.cs`、`VirtualArmRig.cs`、`AnimationComparison.cs` 和 Ch03 真实 Humanoid 骨骼。
2. 取得左右手臂关键关节、真实肘部、腕/掌心代理点、肘垫/座椅、grip 的**同一装置坐标系**位置；核对人物缩放、身体坐姿、前臂长度、握持偏置。
3. 用最简单且可复核的几何方法，判断 −30°、0°、+30° 以及一次连续往返中，**在保留 grip 轨迹时肘部能否落入肘垫的合理接触区域**。必要时小范围搜索调整座椅、人体根位置、肩部/身体姿态、肘垫位置；不要无穷遍历或造复杂优化框架。
4. 将“肘骨原点高度”“肘部接触表面（若可估计）”“肘部水平投影”“掌心代理误差”“手/前臂与桌面是否明显互穿”分开记录；能做网格/可视检查最好，无法计算真实接触就明确写“代理量”。

### B. 优先改进 B 方案

1. 保留现有三档身体姿态插值 + 手脚 IK；在 A 中发现可行布局后，以**必要、少量、易读的参数或代码调整**实现更稳的坐姿与肘垫关系。可以自行调整合理的身体与座椅/垫相对摆位、肘部 hint、姿态端点；尽量避免对 grip 路径作仅为视觉好看的改动。
2. **不得通过不真实地拉伸骨骼、把骨原点硬压到肘垫平面、隐去手臂或大幅移动相机来伪装成功。** 如果原演示机械轨迹与原模型尺寸无法同时满足接触条件，保留可复现的最佳方案并说明不可达区间及需真实机械尺寸确认的量。
3. 保持手掌目标跟随同一 grip，避免修好肘部却让手明显脱离；检查手腕不过度折曲、肩部不过度旋转、脚和臀部仍大致支撑在场景中。
4. 暂缓手指逐关节抓握、复杂表情和全身物理驱动。若接触几何明显可行且剩余时间适合，可顺手做最小手掌朝向/穿模改善，但不将其作为完成门槛。

### C. 验证与交付

- **相同输入前后对比**：建议复用 P1-A 的 −30°、0°、+30° 与 181 帧往返；优先沿用现有 `AnimationComparison.cs` / 角度注入代码，而不是重复造演示工程。
- 展示至少正面、侧面两个相机下的三个姿态，并对比改进前后：掌心到 grip 的代理误差、肘部水平投影/合理表面接触、腕折角、明显穿模和连续运动；原始素材保留本地，公开报告只写允许发布的数值与文字。
- **不把某个任意毫米阈值当成必须通过的 KPI。** 希望肘部在典型角度能够合理接触垫面，且整体画面比 P1-A 明显改善；如果实际不可达，则提供清楚的几何原因、最小替代方案和待测尺寸，不要伪造成功。
- P0 胶囊模式与本地 Ch03 离线比赛 UI 流程不得回退；Editor Play 和静态检查能运行则复测。未实测的项目明确标注。
- 更新少量文档（例如 `docs/P1B-elbow-contact-result.md`、`TASKS.md`、README 必要部分），说明动作模式、参数、演示/实物差异、结果、证据目录与下一轮重点。
- 提交并推送 `feat/p1b-elbow-contact`，可建 **base=`feat/p1-animation-spike`** 的新 PR；不要合并 P0/P1-A/main。
