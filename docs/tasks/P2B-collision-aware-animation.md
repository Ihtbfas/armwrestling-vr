# P2-B｜Rocketbox 骨骼碰撞体与局部防穿模试验

> **状态：待 Codex 执行。** 基于 P2-A 已完成的 `feat/p2a-avatar-paired-grip` / `111e65d` 和 [PR #8](https://github.com/Ihtbfas/armwrestling-vr/pull/8)（目前未合并 main）。本轮先小规模实验，目的不是让人物成为完整物理仿真体，而是**让手—手、上臂—身体的明显穿模可检测、可解释、能在不破坏已有动画的情况下有所改善**。

## 先读并确认

- [调研与官方文档](../research/P2B-unity-collision-aware-animation.md)、[P2-A 实际结果](../P2A-avatar-and-paired-grip-result.md)、`AGENTS.md`、`Assets/ArmWrestling/Scripts/Presentation/{PairedGripPose,PlayerArmVisual,OpponentAvatar,VirtualArmRig}.cs`。
- 核对真实 Unity 中国版 `2022.3.62f3c1` 环境、现有 Rocketbox 和 `NeutralPairedGrip.asset`，先用原 `ArmWrestlingMain` 的 P2-A 角色复现图片中手指穿插/上臂进入胸前的问题。
- **方案遇到问题先查成熟做法**：Unity 的 Collider、`Physics.ComputePenetration`、骨骼 Capsule 以及已经存在的握姿编辑器；已有调研给出原始链接。不要在未看原场景效果前扩大框架或引入新的 VR SDK。

## 第 1 部分：可见的碰撞诊断（必须先完成）

1. 基于两个人物**运行时实际骨骼**建立少量贴合尺寸的碰撞代理，优先级是：玩家/对手掌心与拇指/主要指节；对手上臂、前臂与自身胸肩；肘垫。可用 Sphere/Capsule/Box Collider，必要时适当补充。不要逐三角形求精确模型碰撞。
2. 给 Editor 提供简单可靠的调试显示与数值：Collider 可视开关、在指定角度的相交部位、`ComputePenetration` 等返回的重叠方向/深度。对比可见蒙皮、合理调整 Collider 尺寸；不要让碰撞代理远大于真实手掌，导致大量假阳性。
3. **配对碰撞过滤**：区分预期的指腹贴近/掌面接触、同一身体相邻骨段的正常互穿、真正不合理的双手穿插和上臂穿胸。不要要求每对 Collider 永远 0 重叠。
4. 首先在 0° 找到至少一个有意义的可重复问题，并在 −30°/+30° 复现；记录旧代码/新诊断的数据及真正对应的画面。检测正确前不急着修改骨骼。

## 第 2 部分：有限、不会破坏机械轨迹的自动修正

1. **优先修正最明显的 1～2 处穿模**，例如拇指根部/指节进入另一手、对手上臂进入自身胸部；需要哪条先做可根据实图判断。允许用碰撞结果驱动少量局部指骨旋转、对手肩/躯干姿态或肘部提示目标改变，或重新调整一套配对零位握姿。
2. 手指修正保留两腕**共同 Grip Anchor** 的腕位姿关系；上臂/躯干修正不得直接移动握持点、过度拉长肢体或明显破坏肘垫支撑。先保证正常、自然的扳手腕握姿，避免为了清空碰撞计数把双方手整体拉远。
3. **正确处理动画时序**：本项目 Animator IK 与骨骼手势在 Update/OnAnimatorIK/LateUpdate 写入。确保检测确实使用当帧最终骨骼，修正能保留到渲染，不因 Animator 下一步覆盖而形同虚设，也不能累积旋转导致漂移/抖动。
4. 若发现原姿态或手臂可达性根本不允许局部修正，保留可运行的碰撞诊断和目前 P2-A 最优画面，明确几何原因与建议的下一步；不为了报告好看而伪造穿模已经解决。

## 第 3 部分：公平 A/B 验证及交付

- 为 P2-B 提供**可切换的诊断/修正开关**，默认保留 P2-A 稳定模式。不要修改单自由度角度管线、人物资源根目录或现有主比赛流程。
- 同一 Rocketbox、同一坐标/相机、相同 `−30° / 0° / +30°` 与大约 181 帧往返，比较：
  - 第一人称/双手近景/正侧面在**实际渲染上**哪些穿模减少、哪些仍在；
  - 代理 Collider 诊断按部位的穿入数量/峰值（若可度量），但不要当真实网格接触结论；
  - 手腕相对 grip 误差、腕折角、对手肘部活动与肘垫接触是否退步；动画有无抖动或突然跳跃。
- 尽量复用原有 `AnimationComparison` 和 `P0Validation`，实际 Windows Unity Editor Play 与胶囊、P1-E（本地资源存在时）、P2-A、P2-B 原流程回归；不必为单一问题重建测试环境。

## 阶段完成要求

这是一轮**验证物理碰撞能否帮助我们做动画**的技术试验，而非保证完全无穿模。若碰撞诊断可靠，且至少一处明显穿模获得真实画面上的改善、主握点与比赛流程不倒退，就可先结束并交付。若无法得到自然且稳定的实时修正，也可以完成可用诊断并说明失败原因与可行替代；不允许仅因为新增 Collider 或测试为绿，就宣称防穿模成功。
